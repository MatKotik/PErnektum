# 🤖 Агент поиска работы

Агент каждые 20 минут опрашивает сайты вакансий и присылает **новые** вакансии тебе в Telegram.
Он работает бесплатно на GitHub Actions, поэтому держать компьютер включённым не нужно.

```
сайты вакансий ──► фильтр по критериям ──► убрать уже отправленные и дубли ──► Telegram
```

## Как запустить (≈10 минут)

### 1. Создай Telegram-бота
1. Открой в Telegram [@BotFather](https://t.me/BotFather), отправь `/newbot` и придумай имя.
2. BotFather пришлёт **токен** вида `123456789:AA...` — это `TELEGRAM_BOT_TOKEN`.
3. Найди своего бота и нажми **Start** (без этого он не сможет тебе писать).

### 2. Узнай свой chat id
Напиши что-нибудь своему боту, потом открой в браузере
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найди `"chat":{"id":123456789` — это число и есть
`TELEGRAM_CHAT_ID`. Другой способ: написать боту [@userinfobot](https://t.me/userinfobot).

### 3. Добавь секреты в GitHub
Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

Токен в секретах никто не увидит, даже в публичном репозитории. Пока секретов нет, агент на GitHub
ничего не опрашивает и только оставляет предупреждение на странице запуска.

### 4. Влей ветку в `main`
GitHub запускает задания по расписанию только из основной ветки.

### 5. Проверь
**Actions → Job Agent → Run workflow → mode: `test-telegram`**. В Telegram должно прийти
«✅ Связь с агентом есть». Дальше агент запускается сам каждые 20 минут.

На первом запуске агент только запоминает вакансии, которые уже висят на сайтах, чтобы не прислать
сразу пару сотен. После этого он присылает всё, что появилось позже. Это поведение задаётся
настройкой `agent.first_run` в `config.yaml`.

## Критерии поиска

Всё настраивается в [`config.yaml`](config.yaml). **Пока критерии пустые, агент присылает всё подряд**
(не больше `max_per_run` = 25 вакансий за раз), так что лучше заполнить хотя бы `keywords`:

```yaml
search:
  query: "python"                  # отправляется в поиск на сайтах, где он есть
filters:
  keywords: [python, django, бэкенд]   # нужно хотя бы одно совпадение
  exclude_keywords: [senior, lead]     # вакансия отбрасывается, если встретилось
  remote_only: true
  max_age_days: 3
```

Короткие слова (`go`, `qa`, `1с`) ищутся только целиком, поэтому `go` не находит `google`.
Длинные слова ищутся по подстроке, поэтому «разработчик» находит и «разработчика».

Репозиторий публичный, и `config.yaml` видят все. Если не хочешь светить критерии, положи их в секрет
`JOB_AGENT_OVERRIDES` в формате YAML. Он накладывается поверх `config.yaml`:

```yaml
filters:
  keywords: [python]
```

Каждый сайт можно выключить (`enabled: false`), задать ему свой `query` или свой `interval_minutes`.

### Добавить Telegram-канал или сайт с RSS
```yaml
sources:
  telegram:
    channels: [geekjobs, имя_канала]     # имя без @, канал должен быть публичным
  rss:
    feeds:
      - name: my-site
        title: "Мой сайт"
        url: "https://example.com/jobs.rss?q={query}"
```

## Запуск на своём компьютере или сервере

```bash
cd job-agent
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=...

python -m jobagent --dry-run --preview 2   # посмотреть, что находится, ничего не отправляя
python -m jobagent --test-telegram         # проверить связь с ботом
python -m jobagent                         # один проход
python -m jobagent --loop                  # работать постоянно (круг раз в interval_minutes)
python -m jobagent --only habr_career,telegram --force   # опросить только эти сайты прямо сейчас
```

Память агента (что уже отправлено) хранится в `state/state.json`. На GitHub она лежит в кэше
Actions и передаётся от запуска к запуску.

## Как это устроено

```
job-agent/
├── config.yaml              ← настройки и критерии
├── jobagent/
│   ├── agent.py             ← один цикл: опрос → фильтр → дедупликация → отправка
│   ├── filters.py           ← критерии
│   ├── storage.py           ← память: отправленные вакансии, интервалы, ошибки сайтов
│   ├── notify.py            ← Telegram / консоль
│   └── sources/             ← по модулю на каждую группу сайтов
└── tests/                   ← python -m pytest
```

- **Дубли.** Одна и та же вакансия (название + компания) с разных сайтов приходит один раз.
- **Ошибки сайтов.** Если сайт упал или поменял формат, остальные продолжают работать. Если сайт
  не отвечает 6 раз подряд, в Telegram приходит предупреждение.
- **Лимиты.** Каждый сайт опрашивается не чаще, чем он сам просит: Remotive раз в 6 часов,
  Jobicy раз в час. Telegram получает не больше одного сообщения в секунду.
- **Новый сайт** — это класс-наследник `Source` с декоратором `@register` в `jobagent/sources/`.

## Ограничения

- GitHub не гарантирует точное время запуска по расписанию: задержки в 5–15 минут — норма.
- Если в публичном репозитории 60 дней не было никакой активности, GitHub выключает расписание и присылает об этом письмо.
  Включить обратно можно одной кнопкой во вкладке Actions.
- Telegram-каналы читаются через веб-превью `t.me/s/…`. Посты там не размечены как вакансии, поэтому
  без `keywords` будут приходить и рекламные, и обзорные посты.
